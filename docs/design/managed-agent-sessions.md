# 工作区内多 Agent 会话

## 目标与边界（2026-11-19）

功能分支 `feat/orca-agent-management`，基线 `44bcc2cb`。这是实施记录，不是上线或验收声明。

插件页面只保留账号登录入口。用户在 DSH 当前工作区的原生侧栏新建、查看和继续不同 Agent 的会话，通过 Agent 标识区分，和原有 DSH 会话并列。不新增独立聊天页面、虚拟工作区入口，不导入插件之外的 Agent 历史。

抽取 Orca 的 Agent 管理子系统，在插件内运行，不连接 Orca 桌面或守护进程。迁移范围包含注册与能力描述、运行环境、会话创建恢复、进程生命周期、消息与工具事件、选项、审批及取消。源码复用须记录来源提交和保留 MIT 声明。不能把两个后端适配器的完成写成整个子系统完成。

## 分工与接口

- 管理内核：`packages/plugin/src/managed-agents/`，Agent 注册、运行生命周期与提供方适配；任务属于 Host，不属于一个手机连接。
- 持久化：`packages/plugin/src/managed-session-store/`，账号/Host/工作区归属、稳定会话 ID、提供方会话映射、操作回执、顺序事件和恢复游标。
- 原生集成：混合会话目录、原生工作区成员关系、按插件所有权分发请求，以及侧栏标识。普通 DSH 请求保持原有分发。
- 组合层：连接可信 Host 身份、工作区路径、管理内核与持久化，并经现有认证通信承载访问。

会话的归属字段由 Host 的可信上下文产生，不能信任客户端提交的 ownerId 或任意 cwd。新建操作先持久化幂等标识，再启动提供方。发送接受、提供方确认和结果完成分别记录；响应丢失时不把不确定的发送自动再次执行。提供方可能要求自身日志来恢复上下文，允许按已登记的提供方会话 ID 恢复，不允许扫描后导入其他历史。

事件落盘后才能通知观察端。重连按游标补读，同一事件 ID 不重复追加。关闭页面、断线或撤销某个观察设备只终止其读写与订阅，不停止 Host 持有的任务。停止任务必须是有权限的显式操作。

## 实施顺序

1. 并行梳理 Orca 依赖、DSH 原生扩展接口和 Remote 生命周期，统一边界。
2. 实现可测试的管理内核、持久化与原生组合接口。
3. 组合到实际插件启动路径，验证一个工作区内 DSH 与外部 Agent 同时存在并正确分发。
4. 复用登录与设备通信完成多端订阅和恢复；明确手机协议是否需要更新。
5. 构建隔离安装包，执行实际 DSH 验证，再进行手机/平板真机验收。

## 已确认的约束

DSH 当前 Agent 工厂是单注册，不应替换全局工厂接管原有对话。已有 Remote 虚拟 Harness 能投影到原生控制器，但默认历史扫描和独立虚拟工作区不符合本需求。新实现必须明确使用插件会话登记表和真实工作区归属。

当前生产服务、Nginx、DNS、证书不属于本次开发变更范围。

## 本轮实现与验证

实现位于 `packages/plugin/src/managed-agents/`、`managed-session-store/`、`managed-agent-backend.ts` 和 `managed-agent-gateway.ts`。Orca 源码清单、许可及尚未迁移的能力见管理内核内的 `EXTRACTION.md`；本轮不能表述为整个 Orca 已迁移完毕。

开发开关为插件配置 `managedAgents: { enabled: true }`。初始开发默认关闭；测试发行版 `0.7.0-xcodex.1` 默认启用，显式 false 仍保留。启用后必须先用已有登录流程登录并让 Host 上线。插件页面保留登录，侧栏增加当前工作区的 Agent 新建按钮，聊天使用 DSH 原生界面。测试使用独立 DSH 配置目录、模拟登录服务和端口，不覆盖已有安装或账号。

实际 DSH 集成修正了以下仅靠 mock 无法发现的问题：0.2.2 的工作区目录来自 `workspace/follow` 初始快照；插件自定义操作须走已注册控制路由；原生会话列表会过滤自定义 Agent 标识，所以 Logo 通过独立会话目录映射；模型目录是全局接口，须合并本机 CLI 模型并提供每条会话的真实默认模型投影。

发送结果分三类：已接受、确定未投递、结果未知。确定未投递记录失败并允许用户用新请求 ID 重试；相同请求 ID 不重复执行。结果未知保守阻止继续发送，仍待实现显式核对/恢复交互。Provider 退出后沿用持久 ID 恢复，已退出进程的迟到事件不能影响新进程。以上不承诺 Host 崩溃后仍能继续原来的在途任务。

全量测试后又补充一项“Provider 启动中撤销请求，不能继续派发”的回归测试，Backend 18 项通过，类型检查和最终构建通过。发送和审批在异步连接完成后再次检查请求生命周期及账号归属。
